Show Panel

Opens the dockable Sentinel pane, which shows the model's live rule results, the project's journey from the web, and the Doctor log.

Show Panel opens (or brings forward) the pane titled "Sentinel — Live Coordination". It first appears docked on the right of the Revit window. The button itself does nothing else: it does not scan, sign in or contact the web project.

The pane has four parts. At the top, the Next strip shows where the model's web project stands: the project key and kind, the standards line, the next step the project suggests, the LOD state, the auto-publish line and the line saying which ruleset judged this model. A small "↻" button beside it re-reads all of that from the web (read-only). Below it, a large score line ("Rule pass rate 97.5%", or "Not scored — no ruleset judged this model") sits over a short status line. At the bottom an expandable "Doctor" section holds the running log of what Sentinel did and said. In the middle is the rule grid.

The rule grid lists every rule violation found in the active model, with the columns (first to last) a "⚡ Fix" button, "Rule", "Mode", "Element", "Message" and "Ref". Rows are tinted by enforcement mode: BLOCK (red), REQUEST (orange) and WARN (yellow); BLOCK rows are listed first because they are the ones that stop a sync. Double-click a row to select and zoom to that element in Revit. "⚡ Fix" appears only on naming-rule rows that Sentinel can propose a name for; it opens a "Sentinel — Review Fix" dialog showing the "Current value" and an editable "Proposed value", and nothing is changed until you press "Execute fix". On a REQUEST rule the fix does not rename the element: it files a proposal that a coordinator approves in Change Requests.

The pane fills itself automatically when a project document is opened or synchronised, and again when you press Scan Now or run IFC Pre-Flight; between those it updates live as elements change. Keep it open while you work: it is where the other Sentinel commands report their results (for example the Doctor log carries the confirmation lines that publish, auto-heal and AI-proposal reports leave there).

Before you start

  • No document is needed to open the pane, but it only shows results once a project (not family) document is open and its ruleset has loaded; until then the status says it is loading its ruleset, or the score reads "Not scored — no ruleset judged this model".
  • For the Next strip to show anything, the model must be bound to a web project (Sentinel ▸ Project Setup). Unbound, the strip reads "Journey — not bound — Sentinel ▸ Project Setup".
  • The Next strip needs the Sentinel bridge to be reachable; if it is not, the strip says "Journey unavailable" with the reason.

What you provide

↻ (refresh button on the Next strip)
Re-reads the project's journey and publish policy from the web. Read-only; the Doctor log records what it read.
Row double-click
Selects and zooms to the element in the rule grid row.
⚡ Fix
Opens the Review Fix dialog: check or edit the "Proposed value", then press "Execute fix" (or "Cancel").
Doctor
Expand the section at the bottom of the pane to read the log (newest line first). Its header counts the warnings Revit's Doctor auto-resolved this session and the lines logged.

How to use it

  1. On the Sentinel tab, in the Coordinate panel, click "Show Panel".
  2. Read the Next strip at the top to see the project, standards, next step and publish state; press "↻" to refresh it.
  3. Read the score and status lines under it.
  4. Scan the rule grid; BLOCK rows come first. Double-click a row to jump to the element in Revit.
  5. To correct a naming violation, press "⚡ Fix" on its row, edit the "Proposed value" if needed, and press "Execute fix".
  6. Expand "Doctor" at the bottom when you need to see what Sentinel did or why something was refused.

What you get

  • The pane appears docked in Revit. Nothing is written to the model or the web by opening it.
  • A ⚡ Fix on a WARN or BLOCK row renames the element and removes the row; on a REQUEST row it files a proposal for a coordinator (the row stays until it is approved). The status line says which happened.
  • The Doctor log keeps the last 200 lines for the session.

Tips and limits

If the pane is clipped in a narrow dock, the lines wrap to the dock width and the grid scrolls sideways.
A type-level naming violation has no ⚡ Fix; type renames go through the Naming Manager.
Rows with no real element (for example workset findings) cannot be zoomed to and have no ⚡ Fix.
If the status says "Journey unavailable", the model is bound but the bridge did not answer; the rule grid still works.

Related tools

  • Scan Now — Re-reads the ruleset that judges this model and runs a full compliance scan, showing the result in the Sentinel pane.
  • Change Requests — Lists the change requests waiting for a coordinator and lets a lead or owner approve or reject each one.
  • Naming Manager — Reviews family and type names against the office naming rules, proposes compliant names and renames only the rows you tick.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
  • Rule Set — Lists the rules this model is judged by, with the ruleset's name, version and where it came from.
  • Health Scorecard — Shows a weighted compliance score and a per-domain breakdown of the issues in the active model.
