Governed Publish

Publishes the whole model to the web project through the one governed path: IFC export, delivery gate, IDS and naming check, then a registered version on the ledger.

Governed Publish exports the entire model (no view filter) to IFC in the schema the project's delivery contract asks for (IFC2X3 when no contract is installed), checks that file against the delivery gate, and then asks the Sentinel bridge to judge the model's elements against the project's IDS and the model's file name against the project's naming standard. Each step is recorded on the project's ledger.

If the verdict is accepted (or recorded, meaning nothing could be judged because no IDS applies), the bridge registers one new version of the model container, and the exported IFC is queued in the upload outbox so its geometry attaches to that version. If the verdict is rejected, nothing is registered or uploaded, the failure is held on the web under Project Files > On hold, and each failing requirement opens as a BCF issue on the failing elements, which syncs to the web Issues panel and back into Revit.

The container name comes from the central model's file name for a workshared model, otherwise from the model's own file name, with the .rvt/.rte extension replaced by .ifc. A final dialog names the container, the revision, the ledger rows written and what judged the model. Use it whenever a model is ready to go to the project; it is the only manual publish path for the model itself (Auto-publish on save uses the same steps when the project's publish standard says so).

While the referee is judging, Revit is free to use; only the IFC export itself keeps Revit busy.

Before you start

  • A Revit project (not a family) must be the active document.
  • The model must be bound to a web project: Sentinel > Standards > Project Setup. Otherwise the dialog says the model is not bound and nothing is exported.
  • The Sentinel bridge must be running and reachable. If it is not, the export and the gate still run, but the final dialog says the bridge returned no verdict and nothing is registered or uploaded.
  • No other publish may be running in this Revit session (Governed Publish waiting for the referee, or Auto-publish). Otherwise a dialog asks you to run it again after that one finishes.
  • For a real verdict the project (or its office) should have an IDS and a naming standard installed; with no IDS the verdict is recorded, not accepted, and the dialog says the model was not judged. A delivery contract is optional; without one the gate reads NOT CHECKED.
  • If the office has an IFC export mapping installed, the export uses it; if it is installed but cannot be read, the run is refused before the export. With none installed Revit's default property sets are used and the dialog says so.
  • The active ruleset should carry an office code ("org"); without it, office property sets are not read and the referee reports them missing. The final dialog warns about this.

What you provide

Cancel (on the progress window)
The progress window shows four steps: Export, Delivery gate, Referee and Register. Cancel stops the run at the next safe point. During the export Revit may not honour it, in which case the export finishes and Sentinel then stops; nothing is published.

How to use it

  1. Open the model you want to publish and make sure it is bound to its web project (Project Setup).
  2. Click Sentinel > Publish > Governed Publish.
  3. A progress window appears. Step 1 exports the whole model to IFC; Revit is busy until it ends.
  4. Step 2 checks the IFC against the delivery contract and records the gate row on the ledger, then reads the model's elements for the referee.
  5. Step 3 sends the elements and the file name to the bridge to judge (up to 120 seconds). Revit is free to use meanwhile.
  6. Step 4 registers the version and stages the IFC for upload. The progress window closes and one result dialog appears.
  7. Read the dialog. "ACCEPTED" means the version is registered and the IFC is queued for upload. "REJECTED" lists the naming or element failures; fix them (the BCF issues point at the elements) and run Governed Publish again.

What you get

  • One result dialog: accepted, published-but-not-judged, or rejected, with the project key, IDS line, naming line, delivery gate line, export line, the start of the file's SHA-256, the gate ledger row, the verdict ledger row and the version (container name, revision, state).
  • On accept or record: a new version of the container on the web project and the IFC placed in the upload outbox (%AppData%\Sentinel\outbox) for the bridge to attach as geometry.
  • On a delivery-gate fail: the dialog lists up to 12 failures, the gate row, and where it was held on the web; nothing goes to the referee.
  • On a rejection: no version, no upload; the failure is held on the web (Project Files > On hold) when the bridge records it, and BCF issues are opened on failing elements.
  • The Sentinel pane's Doctor log gets a line saying how many progress updates Revit reported during the export and whether Cancel reached it.

Tips and limits

"This model is not bound to a web project" means Project Setup has not been saved for this model. Nothing was exported.
"A publish of this session is still running" means another publish is waiting on the referee; wait for its dialog, then run again.
"IFC export contained no geometry" means the export produced nothing; check the model's IFC mappings (Export to IFC As).
"The Sentinel bridge did not return a verdict" means the bridge was not reached; start it and run again. Nothing was registered.
A "Recorded" result (not "Accepted") means no IDS applied or nothing was in its scope; the version exists but carries no verdict badge, and publishing it on the web needs the lead's reason.
If the version registered but the IFC could not be moved to the outbox, the dialog says so and names where the IFC was kept; run Governed Publish again.
Cancelling while the referee is judging stops Sentinel waiting, but the bridge may still finish and write its rows.

Related tools

  • IFC Gate — Group of two IFC deliverable checks: Pre-Flight before you export, and Delivery Gate to certify the IFC file.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
  • Sign in — Signs you in with your Sentinel account so everything Revit sends to the project carries your name.
  • BCF Issues — Shows the coordination issues raised on the web (BCF), jumps Revit to each issue's element and camera, and lets you raise new issues from your Revit selection.
  • Health Scorecard — Shows a weighted compliance score and a per-domain breakdown of the issues in the active model.
  • Publish Sheets — Renders every Revit sheet to an image and a PDF for the web app's Sheets tab, and proposes each PDF to the project's document register.

Ribbon tooltip

The one publish path: export the whole model to IFC in the contract's schema, run the delivery gate, adjudicate against the project IDS and naming, and — on accepted or recorded — register one version (the container is named from the central file) with its verdict on the ledger and stage the upload. A reject uploads nothing; each failing requirement auto-opens as a BCF issue (live-synced to the web and back into Revit). The dialog names the version and both ledger rows.
