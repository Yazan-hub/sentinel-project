Change Requests

Lists the change requests waiting for a coordinator and lets a lead or owner approve or reject each one.

Change Requests opens a window titled "Sentinel — Change Requests" with one card per pending request. Each card shows the category of the element, the rule that raised it, the old value struck through next to the new value, who asked and when. Requests come from naming rules in REQUEST mode: when someone renames an element in a way the rule wants reviewed, or files a "⚡ Fix" proposal from the Sentinel pane, it waits here for a decision.

Only a lead or owner of the model's web project can decide. Anyone else (including a signed-out user) sees the list but it is read-only, and the header says why.

"Approve" keeps a change that was already made, or, for a proposal (nothing was applied yet), applies the proposed name. "Reject" puts back the old value for a change that was made, or simply drops a proposal. Each verdict is its own Revit transaction ("Sentinel: Approve request" or "Sentinel: Reject request"), so it can be undone in Revit like any other edit, and the card leaves the list only once the verdict has been written.

Before you start

  • A project document must be open (the command quietly does nothing without one).
  • To approve or reject you must be a lead or owner on the model's web project; the model must be bound to it (Sentinel ▸ Project Setup) and you must be signed in (Sentinel ▸ Sign in). Without that the window opens read-only.
  • Requests live inside the model, so the document must be the one the requests were raised in.

What you provide

Show
Previews the request on the element: it is painted with a green fill and isolated in the active view. For views and sheets it opens or selects them instead. Closing the window restores the original graphics.
✓ Approve
Accepts the request (keeps the change, or applies the proposal).
✕ Reject
Refuses the request (reverts the change, or drops the proposal).

How to use it

  1. On the Sentinel tab, in the Coordinate panel, click "Change Requests".
  2. Read the header: it says how many are pending and whether you can decide ("approve keeps a change (or applies a ⚡ proposal); reject reverts it (or drops the proposal)") or are read-only and why.
  3. For a card, click "Show" to see the element highlighted in the active view.
  4. Click "✓ Approve" or "✕ Reject".
  5. Check the header: the pending count drops when the verdict is written; a red "✕" message appears if it was not.

What you get

  • The element's name (or number, for a sheet) is changed or reverted inside a Revit transaction, and the review flag on the element is cleared.
  • The request leaves the list and its status in the model becomes Approved, Rejected or Reverted, with the deciding person and time recorded.
  • Closing the window clears the Show highlight.

Tips and limits

If you sign in as someone else while the window is open, further verdicts are refused with "read-only — the signed-in person changed since this window opened"; close and reopen the window.
An approval of a proposal can fail with "'<name>' is already in use — reject this proposal or rename by hand." The request then stays pending.
If Revit does not save the verdict (another user owns the element) the card stays and the header says so.
The read-only header messages include: not bound to a web project, your role could not be read, signed out (sign in as a lead or owner), not a member, or the role you hold.
If you reject a proposal after someone had already renamed the element by hand, Sentinel keeps the hand rename when it passes the rule and reverts it when it still breaks the rule.

Related tools

  • Show Panel — Opens the dockable Sentinel pane, which shows the model's live rule results, the project's journey from the web, and the Doctor log.
  • Review Flag — One-time project setup: creates the ZZZ_ReviewStatus flag parameter on Views, Sheets, Levels and Grids so pending changes can be grouped in the Project Browser.
  • Naming Manager — Reviews family and type names against the office naming rules, proposes compliant names and renames only the rows you tick.
  • Sign in — Signs you in with your Sentinel account so everything Revit sends to the project carries your name.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
