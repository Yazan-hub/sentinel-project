MEP Type Check

Checks every duct, pipe, cable tray and conduit in this model against the office type catalogue: the type, and the system type for ducts and pipes.

MEP Type Check reads the ducts, pipes, cable trays and conduits of the active model (not its links) and compares each one's type with the type catalogue installed on the model's web project or office. For ducts and pipes it also compares the system type against the office's.

The result groups elements by category and verdict: matched, type not the office's, system not the office's, or no system. Systems are judged only on elements that already have the office's type. Categories the catalogue has no rows for are counted as not checkable.

It is strictly read-only: nothing in the model changes. It does not check sizes, because the office has no size list, and it does not retype. It does not read flex ducts and pipes, placeholders, fabrication parts, fittings or accessories.

Before you start

  • A project document (not a family) open and active.
  • The model must be bound to its web project via Project Setup. If not, you see: "This model is not bound to a web project — Sentinel ▸ Project Setup."
  • A type catalogue installed on the web project or office. If none, the message is "No type catalogue installed (...) — nothing to check against; nothing was sent."
  • The catalogue's category names must be in English (Ducts, Pipes, Cable Trays, Conduits).

What you provide

Export a BCF topic… (button, only when something does not match)
Opens a folder choice; the file name is generated.

How to use it

  1. Make the MEP model the active document.
  2. On the Sentinel tab, in the Validate panel, click "MEP Type Check". The catalogue is fetched first; allow up to 20 seconds.
  3. Read the dialog "Sentinel — MEP Type Check": the headline counts and up to 12 findings.
  4. If elements do not match, optionally click "Export a BCF topic…" and choose a folder, then Close.

What you get

  • A dialog with the counts (checked, matched, type not the office's, system not the office's, no system, not checkable, without a type) and the first 12 findings.
  • One MEP check row sent to the project ledger. The dialog notes that the pane's Doctor log says whether it landed.
  • Optional .bcfzip of the unmatched elements, with up to 100 element ids; nothing is raised on the web.
  • The model is not changed.

Tips and limits

"No ducts, pipes, cable trays or conduits in this model" is shown when there is nothing to check.
Elements with no type are counted separately and not judged.
The BCF is a local file only.

Related tools

  • MEP Openings — Finds where linked MEP crosses native walls, floors and structural framing and offers to place tracked provision-for-void markers or export a BCF.
  • Clash — A drop-down group holding the two clash tools: Clash Manager (run clash detection in this model) and Clash Register (read the team-wide clash register from the web).
  • BCF Issues — Shows the coordination issues raised on the web (BCF), jumps Revit to each issue's element and camera, and lets you raise new issues from your Revit selection.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
  • Standards — A drop-down group for binding a model to its web project, signing in, and building, applying or ingesting office standards.
