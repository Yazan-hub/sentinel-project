MEP Openings

Finds where linked MEP crosses native walls, floors and structural framing and offers to place tracked provision-for-void markers or export a BCF.

MEP Openings looks for intersections between MEP in linked models (IFC drops and Revit MEP links) and the native walls, floors and structural framing of your model. Several crossings within about 150 mm of each other on the same host are merged into one candidate, so a bundle of pipes through one wall zone becomes a single opening.

Before offering new candidates it reconciles the voids it has placed before, against the current link: voids whose MEP moved are relocated, voids whose MEP has gone are marked Orphaned, and voids already marked Cut are left alone because the opening physically exists. The dialog reports how many were relocated, orphaned and unchanged.

For the new candidates you choose to place tracked provision-for-void families, or to export a BCF topic to send to the MEP engineers.

Before you start

  • Linked MEP or IFC models must be loaded in the project. If no intersection is found, the dialog says "No intersections found" and asks you to check that the IFC/MEP links are loaded.
  • To place voids: a Generic Model family with "Void" or "Provision" in its name loaded in the project, and an office code in the ruleset, because the tracking parameters are named from it. Without the office code, placement is unavailable and the message "No office code configured (ruleset 'org' is empty)..." is shown.
  • The model must be the active document when the job runs; if not, Sentinel tells you to switch back.

What you provide

Place tracked provision-for-void families
Places one instance per merged candidate, setting its void id and a status of Pending.
Export to BCF (send to MEP engineers)
Choose an output folder in a save dialog; the file name is generated. One topic is made for the affected hosts.

How to use it

  1. Load the MEP or IFC links and make your model the active document.
  2. On the Sentinel tab, in the Validate panel, click "MEP Openings".
  3. Read the dialog: the number of new candidates and how many existing voids were relocated, orphaned and unchanged.
  4. Click "Place tracked provision-for-void families" or "Export to BCF (send to MEP engineers)", or Cancel.
  5. For BCF, choose a folder in the dialog "Choose BCF output folder"; the file name is automatic.

What you get

  • Placing: voids are placed in the model in one step. A dialog reports how many were placed and how many were skipped (no family or bad point).
  • The reconcile pass has already moved or flagged existing voids before the dialog appears.
  • BCF: a .bcfzip with a topic titled "Provision for void required", listing up to 20 candidates and up to 100 host elements, with camera and snapshot. Open it in BIMcollab, Solibri or Navisworks. The dialog shows the file path.
  • Nothing is posted to the web ledger by this tool.

Tips and limits

Cancelling the dialog does not undo the reconcile pass that ran first.
If no matching family is loaded, zero are placed and all candidates are reported as skipped.
BCF only lists host elements from your model; linked element ids cannot be addressed in your model.

Related tools

  • Clash — A drop-down group holding the two clash tools: Clash Manager (run clash detection in this model) and Clash Register (read the team-wide clash register from the web).
  • Clash Manager — Detects clashes between linked MEP/IFC models and your native structure, grades them by severity, and lets you open a coloured 3D clash view or export them to BCF.
  • BCF Issues — Shows the coordination issues raised on the web (BCF), jumps Revit to each issue's element and camera, and lets you raise new issues from your Revit selection.
  • MEP Type Check — Checks every duct, pipe, cable tray and conduit in this model against the office type catalogue: the type, and the system type for ducts and pipes.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
