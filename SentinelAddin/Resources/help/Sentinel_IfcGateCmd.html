IFC Delivery Gate

Exports the model to IFC (or opens an existing IFC) and certifies it against the delivery contract, recording the verdict on the project ledger.

IFC Delivery Gate checks an IFC file against the delivery contract installed on the model's web project (or its office). The result is a certificate with a clear verdict: pass, FAIL (do not upload this file to the common data environment) or NOT CHECKED when no contract applies. NOT CHECKED is never shown as a pass.

You choose one of two routes. "Export the whole model to IFC, then certify" runs Revit's IFC exporter on the whole model, using the contract's schema (IFC4 Reference View, or IFC 2x3 CV2), then validates the file. "Certify an existing IFC file" validates a file exported by anyone, from any source.

The verdict and the contract that judged are posted to the project ledger as a check. A check holds nothing on the web: it does not create a version or upload anything. For that, use Governed Publish.

Before you start

  • A document must be open.
  • For a pass or fail verdict, a delivery contract must be installed on the web project or office and the model bound to its project via Project Setup. Without one the file is only fingerprinted and the certificate says nothing was judged.
  • For the export route: the model must have exportable geometry. If an office IFC export mapping is installed it is used for property sets; otherwise Revit's defaults are used. A saved Revit IFC export setup is not used.
  • For the ledger record: the Sentinel service must be reachable. If not, the dialog says it was not recorded or not confirmed.

What you provide

Certify an IFC deliverable (choice)
"Export the whole model to IFC, then certify" for a fresh export, or "Certify an existing IFC file" for a file you already have. The dialog's first lines name the contract and the IFC schema the export will use.
Export IFC deliverable (save dialog)
Where to save the exported .ifc. The name defaults to the model title. The file type follows the contract (IFC4 or IFC 2x3).
Select IFC file (open dialog)
For the existing-file route: the .ifc file to certify.

How to use it

  1. Make active the model you want to deliver (for the export route).
  2. On the Sentinel tab, in the Validate panel, open "IFC Gate" and click "IFC Delivery Gate".
  3. In the dialog "Certify an IFC deliverable", read the contract line, then choose an export or an existing file. Choose Cancel to leave.
  4. Pick the save location (export) or the file (existing). For an export, Revit pauses until the export finishes.
  5. Read the result dialog: verdict, contract, schema, entity counts, coverage per requirement, failures and warnings, the certificate location, and the file's SHA-256 fingerprint.
  6. Read the last line: "Recorded: ledger #… · receipt …" means the verdict is on the project ledger.

What you get

  • The exported .ifc at the place you chose (export route).
  • A certificate file whose path is shown in the result dialog, with the start of the file's SHA-256.
  • A result dialog that begins with a pass, FAIL or NOT CHECKED line. A pass reminds you that IDS is not checked here; Governed Publish judges that.
  • One ledger row for the check, with the contract used. The dialog says whether it was recorded, not confirmed, not recorded, or not sent because the model is not bound.

Tips and limits

FAIL means do not upload the file. Fix the failures listed, re-export and run the gate again.
"IFC export contained no geometry — nothing to certify" means nothing exportable came out; check the model's IFC mappings (Export to IFC As).
If an installed office IFC export mapping does not parse or could not be confirmed, the export is stopped with a message and nothing is exported.
The export runs when Revit is next free. If you switch to another open model before it runs, Sentinel asks you to switch back and exports nothing.
An unbound model is still certified locally, but nothing is recorded on the web.

Related tools

  • IFC Pre-Flight — Audits the model before IFC export for missing 'Export to IFC As' mappings and for the properties the delivery contract requires.
  • Governed Publish — Publishes the whole model to the web project through the one governed path: IFC export, delivery gate, IDS and naming check, then a registered version on the ledger.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
  • Sign in — Signs you in with your Sentinel account so everything Revit sends to the project carries your name.
  • BCF Issues — Shows the coordination issues raised on the web (BCF), jumps Revit to each issue's element and camera, and lets you raise new issues from your Revit selection.

Ribbon tooltip

Export + certify an IFC against the delivery contract installed on this document's web project (or its office), named contract@n with source and sha; the export uses the contract's IFC schema. FAIL = do not upload to the CDE; no contract = NOT CHECKED, never a pass.
