Naming Manager

Reviews family and type names against the office naming rules, proposes compliant names and renames only the rows you tick.

Naming Manager scans the families and types the naming rules apply to and gives each a verdict. Conforming: the name already follows the rule. Proposed: Sentinel has built a compliant name from the model's facts (for example a wall's thickness, function or layer materials) and shows it for you to accept or edit. Needs a human: it cannot complete the name and shows its best guess for you to complete. Blocked: the proposed name would duplicate an existing one, which is a human decision, so it is never renamed here.

Nothing is renamed until you tick it. You can tick all proposed rows at once, edit any proposed name, or use the "Fix" button on a row to open a review dialog for that one element. For Needs a human rows, a live line shows whether your name matches the rule and what is wrong.

A batch is applied in one Revit transaction. Each rename is re-checked against the rule and for uniqueness at the moment of writing, the change is added to the audit trail, and the whole batch is posted as one ledger row. The status line tells you whether the ledger accepted it.

Before you start

  • A project document open and active.
  • The Sentinel rule engine running (otherwise the message tells you to restart Revit).
  • A ruleset installed on the web project or office containing at least one family or type naming rule. If not, the message says the ruleset has no family or type naming rule and to install one first.
  • An office code in the ruleset for rules that use it; otherwise those rows read as needs a human.
  • Binding via Project Setup for the ledger row. An unbound model still renames locally; the status says the row was not sent.
  • Only one Naming Manager window can be open at a time ("The Naming Manager is already open.").

What you provide

Rule / Category / Verdict / Search
Filters for the list. Search matches the current or proposed name.
Proposed name (text box per row)
The name to apply. Editable on Proposed and Needs a human rows. A good value matches the rule's pattern.
Tick box (per row)
Only ticked rows are renamed.
Tick all proposed
Ticks every visible Proposed row.
Untick all
Clears the ticks.
Select instances
Selects and shows the instances of the first ticked row's type or family in the model. Says "Tick a row first." if none are ticked, and "No instances of that type in the model." when there are none.
Rescan
Re-reads the model. Unsaved edits to proposed names are discarded.
Rename ticked
Applies the ticked rows. Says "Tick at least one row with a name to rename." if nothing qualifies.
Fix (per row)
Opens the review dialog for one element and renames it when you confirm.

How to use it

  1. Make the model the active document.
  2. On the Sentinel tab, in the Validate panel, click "Naming Manager".
  3. Use Rule, Category, Verdict and Search to narrow the list. The status line shows counts: shown, conforming, proposed, needs human, blocked.
  4. Review each row: category and family, current name, proposed name, verdict and the number of instances.
  5. Edit proposed names where needed. Click "Tick all proposed" or tick rows individually.
  6. Click "Rename ticked". The buttons are disabled while it runs.
  7. Read the status line: "Renamed n/m", any rows not renamed with the reason, then the ledger line once the bridge answers.
  8. Click "Rescan" to confirm the list is now clean.

What you get

  • Families and types are renamed in the model in one transaction.
  • Each rename is recorded in the model's audit trail and the batch is one ledger row on the project, with the old and new names and the rule. The status line says Recorded with a ledger number and receipt, or not confirmed or not recorded and why.
  • The list refreshes after a rename.

Tips and limits

Rows are refused with a reason when the name no longer matches the rule, is empty, or is now taken in that family or category; or "element no longer exists" if it was deleted meanwhile.
If the audit store cannot take the batch, or the transaction does not commit, nothing is renamed.
If you switch to another model while the window is open, actions stop with "switch back to the model the Naming Manager was opened on — nothing was done".
Blocked rows are never renamed from here. Merge or resolve duplicates by hand.

Related tools

  • Scan Now — Re-reads the ruleset that judges this model and runs a full compliance scan, showing the result in the Sentinel pane.
  • Rule Set — Lists the rules this model is judged by, with the ruleset's name, version and where it came from.
  • Heal Loaded Families — Scans the model families already in the project, auto-fixes a missing shared parameter and reports what needs a person.
  • ROI Dashboard — Shows the web project's ledger counts for delivery gate runs, naming renames and family heals, and prices them if the project has an ROI standard.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
