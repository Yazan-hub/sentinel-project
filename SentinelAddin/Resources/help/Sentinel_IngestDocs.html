Ingest Docs

Reads office-standards documents with a local language model and proposes worksets, shared parameters and naming rules for you to review.

Ingest Docs turns a written standard (a PDF, text, Markdown or CSV file) into a reviewable standards pack. You pick one or more documents; a local language model (Ollama, running on your PC) reads them in chunks and extracts workset names, required shared parameters (with data type, instance or type binding, and categories) and naming conventions for views, sheets, families, levels and grids.

The results open in the same review window as Build Office System, with the source file and page recorded for each item. Items found in documents are never pre-ticked: you decide what is real. Nothing is invented on purpose, but a language model can misread, so review each row.

From there you can build the ticked items into the open model, save them as a pack, or run the ISO 19650 check. Ticked worksets and naming rules also go into the web project's ruleset when you build. The documents are read on your own machine; by default nothing is sent to a cloud service.

Before you start

  • Ollama running locally with a model pulled. The default is the model llama3 at http://localhost:11434; the PC can override the address and model with the SENTINEL_OLLAMA_URL and SENTINEL_LLM_MODEL settings. An address on another machine is refused unless this PC's configuration explicitly allows it.
  • A Revit model open (it is the model the pack would be built into).
  • Readable documents: .pdf, .txt, .md or .csv.
  • To build the results into a model: the same requirements as Build Office System (bound to a web project for the ruleset install; workshared for worksets).

What you provide

Ingest office-standards documents (file dialog)
Select one or more documents. Multiple files are allowed. The filter shows pdf, txt, md and csv; All files is also available.
Review window
Tick items to keep, then Build ticked items or Save pack. A pack made from documents has no source model, so Send office snapshot and Install catalogue on office will say to extract from a template first.

How to use it

  1. Start Ollama and make sure the model is available.
  2. Click Sentinel > Standards > Ingest Docs.
  3. Select the standards document(s) and click Open.
  4. The review window opens at once with a status like "Reading N document(s) and querying the local LLM...". The first run loads the model and can take a minute or more; large documents take longer.
  5. When extraction finishes the tree fills in. Tick only what is correct (nothing is pre-ticked).
  6. Click Build ticked items to create the worksets and shared parameters in the model and add the worksets and naming rules to the ruleset, or Save pack to keep the pack for Apply Standard.

What you get

  • A review window with Worksets, Shared Parameters and Naming Rules extracted from the documents, each tagged with its file and page.
  • On build: the same Created, Skipped and Failed report, one Undo entry, ruleset install and ledger row as the other standards tools.
  • Saving writes a pack to %AppData%\Sentinel\packs, named after the first document.
  • Naming rules are given stable ids (NM-01, NM-02, ...) so re-running replaces rather than duplicates them.

Tips and limits

"The local LLM could not be reached ... Start Ollama and pull the model" means Ollama is not running or the model is not installed.
If one chunk of a document fails, the rest still produce results.
A message about the endpoint being refused means the configured model address is not local and this PC has not opted in to a remote one.
Document items carry a confidence below the golden-model level on purpose, which is why they start unticked.
"No worksets, shared parameters or naming rules were found in the document(s)" means the model found nothing it could extract; check the document actually contains readable text.

Related tools

  • Build Office System — Reads the office standard out of the open "golden" model, lets you review and tick it, then builds it into this model and into the project's ruleset.
  • Apply Standard — Loads a saved standards pack from disk and lets you build it into the open model, the golden-to-blank round trip.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
  • Naming Manager — Reviews family and type names against the office naming rules, proposes compliant names and renames only the rows you tick.
  • Rule Set — Lists the rules this model is judged by, with the ruleset's name, version and where it came from.
