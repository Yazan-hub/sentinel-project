Publish Views

Lets you tick which Revit views to render as images for the web app's Views tab.

Views do not survive IFC export, so this tool renders the views you choose to PNG images (about 2400 pixels) and writes a manifest listing them, with each plan view's level. The Sentinel bridge serves them to the web app's Views tab (BIM Tools).

A picker lists every publishable view grouped by type (Floor Plans, Ceiling Plans, Sections, Elevations, 3D Views, Drafting Views and so on), with one checkbox per view. Only ticked views are published; republishing with a view unticked removes it from the web app. The ticks from your last publish are remembered and pre-ticked next time.

It reads the model only. It does not touch the ledger or the governed IFC path.

Before you start

  • An open project bound to a web project (Project Setup). Otherwise a dialog says the model is not bound.
  • At least one publishable view. View templates, legends, sheets and Revit's internal views are not offered; if none remain the dialog says no publishable views were found.
  • The Sentinel bridge running, so the web app can fetch the images.

What you provide

View tree (checkboxes)
Tick each view to publish. Groups are expanded by default; plan views show their level after the name. Views ticked on the last publish are pre-ticked.
Select All / Select None
Tick or clear every view at once.
Publish
Renders the ticked views. The footer shows how many views are available and how many were pre-ticked from the last publish.
Cancel
Closes the picker and publishes nothing.

How to use it

  1. Open the model and make sure it is bound to its web project.
  2. Click Sentinel > Publish > Publish Views (in the Publish drop-down).
  3. In the "Sentinel - Publish Views" window, tick the views you want in the web app, or use Select All.
  4. Click Publish.
  5. Read the confirmation dialog, then open the web app's BIM Tools > Views tab and refresh.

What you get

  • A dialog says how many views were published and the folder, %AppData%\Sentinel\views\<model name>, with a reminder that the bridge must be running.
  • One PNG per view, a manifest.json and a selection.json (the remembered ticks) in that folder. The folder is rebuilt on every run.

Tips and limits

Clicking Publish with nothing ticked gives "Nothing selected - nothing published" and changes nothing.
"View export failed" means the whole run failed; the reason is shown. A single view that cannot be rendered is left out of the web app rather than stopping the run, so the published count can be lower than the number you ticked.
Unticking a view and republishing removes it from the web app, because the folder is replaced each time.
Output is keyed by the model's name, not by the web project.

Related tools

  • Publish Sheets — Renders every Revit sheet to an image and a PDF for the web app's Sheets tab, and proposes each PDF to the project's document register.
  • Governed Publish — Publishes the whole model to the web project through the one governed path: IFC export, delivery gate, IDS and naming check, then a registered version on the ledger.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.

Ribbon tooltip

Choose which views (plans, sections, elevations, 3D, drafting) to publish. Only checked views appear in the web app's Views tab. Keyed by model name under %AppData%, not by the web project — outside the governed IFC path.
