Publish Sheets

Renders every Revit sheet to an image and a PDF for the web app's Sheets tab, and proposes each PDF to the project's document register.

Sheets do not survive IFC export, so this tool renders them itself. For every non-placeholder sheet it writes a PNG (about 2400 pixels wide, for the web Sheets viewer) and, on Revit 2022 or later, a PDF. It also records each sheet's viewports (view name, type, level and where they sit on the sheet) so the web app can link a drawing to its level in 3D.

Each PDF is then proposed to the project: it is named after the sheet number (for example A-101.pdf), judged by the project's naming standard, and registered as a version carrying the sheet's current revision when the bridge accepts it. The bridge also reports whether the sheet is planned in the project's information delivery plan (MIDP). One proposal row per sheet goes on the ledger. A sheet whose name is refused is held on the web and is never renamed.

The model itself is not changed. Run it when drawings are ready for review or issue; the result dialog lists every sheet with what happened to it.

Before you start

  • An open project bound to a web project (Sentinel > Standards > Project Setup). Otherwise a dialog says the model is not bound.
  • At least one sheet in the project. Otherwise the dialog says no sheets were found and asks you to create sheets (View > Sheet).
  • The Sentinel bridge running to serve the images and to take the PDF proposals. If it is not reached, each sheet reads "not proposed" with the reason, but the images are still written.
  • Revit 2022 or later for the PDFs. On earlier versions sheets are exported as images only and read "image only (not proposed)".

How to use it

  1. Open the model and make sure it is bound to its web project.
  2. Click Sentinel > Publish > Publish Sheets (in the Publish drop-down).
  3. Wait while each sheet is rendered and proposed. There is no selection dialog; all sheets are processed. Revit is busy during this, and large sheet sets take longer.
  4. Read the result dialog.

What you get

  • A dialog says how many sheets were exported and how many were registered, then one line per sheet (the first 25): refused with the reason, registered with revision, verdict and MIDP answer, image only, not exported with the reason, or not proposed with the reason. A "... and N more" line covers the rest.
  • Files written to %AppData%\Sentinel\sheets\<model name>: one PNG and one PDF per sheet, plus manifest.json. The folder is rebuilt on every run. The dialog prints the folder path.
  • The web app's Sheets tab (BIM Tools) shows the sheets once the bridge is running.
  • One proposal row per sheet on the web project's ledger, and a registered version of each accepted PDF.

Tips and limits

"No sheets found to export" means the project has no sheets (placeholder sheets are skipped).
"Sheet export failed" means the whole run failed; the reason is shown. A single bad sheet does not stop the run; it is named in the result with its reason.
A refused sheet ("refused - ...") failed the naming standard or another check; it is held on the web for a lead to deal with, and the sheet number is not changed for you.
The sheet's revision is taken from its current revision parameter; if it is empty or longer than 16 characters, the register numbers the version itself.
Output is keyed by model name, so two models with the same title overwrite each other's folder.

Related tools

  • Publish Views — Lets you tick which Revit views to render as images for the web app's Views tab.
  • Governed Publish — Publishes the whole model to the web project through the one governed path: IFC export, delivery gate, IDS and naming check, then a registered version on the ledger.
  • Naming Manager — Reviews family and type names against the office naming rules, proposes compliant names and renames only the rows you tick.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
