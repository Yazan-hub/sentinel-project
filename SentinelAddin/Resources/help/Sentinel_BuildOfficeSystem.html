Build Office System

Reads the office standard out of the open "golden" model, lets you review and tick it, then builds it into this model and into the project's ruleset.

Run this on the office's golden model or template. It reads, without changing anything, the user worksets, the shared-parameter bindings, the view templates, the Project Browser organisation schemes and the full catalogue of family and element types in that model. They appear in a review window, grouped, each with a confidence badge, and the items it is certain of are pre-ticked.

From the review window you can build the ticked items into the model, save them as a standards pack for other models, run an ISO 19650 gap check, send an office snapshot to the web project, or install the type catalogue on the office. Building also installs the ticked worksets and naming rules into the web project's ruleset so the scanner enforces them.

The type catalogue ("Families & Types") is reference only: nothing to tick or build. It is exported to a file at the start of the command, and a lead can install it on the office from the window so Ghost Builder, Photo Massing and Promote read the office's real types.

Before you start

  • A Revit model open; it is the model the standard is read from, and the Build button writes into the model the window was opened on.
  • For the ruleset part of a build, the model must be bound to a web project (Project Setup); otherwise the model is built but the ruleset line says it was not installed because there is no project.
  • Workset items need a workshared model; on a model that is not workshared they are skipped with a message to enable worksharing.
  • View templates and browser organisation schemes are copied from the golden model, so it must be open in the same Revit session when you build into another model; otherwise they are skipped with a message to open the golden model.
  • Send office snapshot needs the model bound to a web project and a pack that came from a model. Install catalogue on office needs you signed in, a pack with a harvested catalogue, and a project that belongs to an office; the bridge checks that you are a lead on that office.
  • While the build runs, the model the window was opened on must still be open and active; if you switch to another model the build refuses and says nothing was changed.

What you provide

Tree of items (checkboxes)
Groups: Worksets, Shared Parameters, Naming Rules, View Templates, Browser Organization. Each row has a confidence badge (green high, amber medium, red low) and its provenance. Items from the golden model start ticked. Untick anything the office should not standardise.
Families & Types
A read-only list of the types in the model by category, for reference. Nothing here is built.
Build ticked items
Builds the ticked worksets, shared parameters, view templates and browser schemes into the model, and installs worksets and naming rules into the project's ruleset. If nothing is ticked it says so.
Save pack
Saves the ticked items as a standards pack file, named after the source model and version, in %AppData%\Sentinel\packs.
ISO 19650 check
Grades the whole proposed standard (not only the ticked part) against ISO 19650 fundamentals and shows the gaps.
Send office snapshot to Sentinel
Sends this pack's worksets, shared parameters, type catalogue and current ruleset to the web project's Documents > READINESS view so the office standard can be measured.
Install catalogue on office
Installs the harvested type catalogue as the office's type catalogue on the web app (a lead's action).

How to use it

  1. Open the golden model or template and click Sentinel > Standards > Build Office System.
  2. Wait for the extraction (it is read-only). The review window "Sentinel - Build Office System" opens, and a dialog reports that the type catalogue was exported and where.
  3. Tick the items you want, and untick the rest.
  4. Optionally click ISO 19650 to see the gaps, and Save pack to keep the pack for other models.
  5. To build into a model, make that model the active document first, then click Build ticked items. (To build into a different, blank model, use Apply Standard there instead.)
  6. Read the report in the window: created, skipped and failed items, followed by the "Ruleset install" outcome.
  7. Optionally click Send office snapshot to Sentinel, or (as a lead, signed in) Install catalogue on office.

What you get

  • The window shows Created, Skipped and Failed lists, then the ruleset install result and a status line such as "Done - N created, N skipped, N failed".
  • The whole build is one Undo entry in Revit named "Apply standard"; if a step fails the build is rolled back.
  • Items that already exist are skipped, so rebuilding only adds what is missing.
  • Shared parameters are bound to the categories that exist in the model. They use the model's shared-parameter file if one is set; otherwise a file is created under %AppData%\Sentinel\shared.
  • When the model is bound and worksets or naming rules were ticked, the project's ruleset gains a new version containing them and the scanner reloads it. If the project was inheriting the office's ruleset, it now has its own and stops inheriting later office changes (the window warns).
  • If Revit kept the build and something was created, one "Apply Standard" row is written to the project ledger.
  • The type catalogue is exported to %AppData%\Sentinel\exports.

Tips and limits

The window title reads "Build Office System" for all three standards tools.
A cached copy of the ruleset is never used as the base for an install: if the bridge did not answer, the model is built but the ruleset is not installed, and the report says to run Apply again when the bridge is up.
Naming rules usually come from Ingest Docs; a golden model supplies worksets, parameters, view templates, browser schemes and the type catalogue.
Only one build can run at a time; pressing Build again while one is running says so.

Related tools

  • Apply Standard — Loads a saved standards pack from disk and lets you build it into the open model, the golden-to-blank round trip.
  • Ingest Docs — Reads office-standards documents with a local language model and proposes worksets, shared parameters and naming rules for you to review.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.
  • Sign in — Signs you in with your Sentinel account so everything Revit sends to the project carries your name.
  • Rule Set — Lists the rules this model is judged by, with the ruleset's name, version and where it came from.
  • 2 · Ghost Builder — Builds LOD 200 Revit geometry (walls, floors, doors, windows and more) from a 2D DWG plan, mapping CAD layers to Revit types by the project's standards, after you review and tick what to build.
