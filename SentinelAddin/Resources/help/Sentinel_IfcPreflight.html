IFC Pre-Flight

Audits the model before IFC export for missing 'Export to IFC As' mappings and for the properties the delivery contract requires.

IFC Pre-Flight looks at the exportable elements of the model (walls, floors, roofs, ceilings, doors, windows, stairs, columns, structural framing and foundations, curtain-wall panels and mullions, and generic models) and checks two things. IFC-01: does the element or its type carry an explicit 'Export to IFC As' mapping? IFC-02: for the properties the delivery contract requires, is each one present and filled on the elements it applies to?

Severity is sensible rather than noisy. A missing mapping on a wall or door is only a MONITOR note, because Revit has a sound default (IfcWall, IfcDoor). A missing mapping on a Generic Model or Specialty Equipment is a WARN, because it will export as a generic building element proxy, which degrades a coordination deliverable. A required property that is missing or empty is a WARN.

Some contract requirements cannot be tested inside Revit, for example whole property sets, or properties Sentinel has no Revit mapping for. These are listed as "not checked here" notes. They are neither counted as issues nor treated as clean: the IFC Delivery Gate checks them in the IFC file itself.

The check is read-only, so run it as often as you like before exporting.

Before you start

  • A model with placed elements open and active. An empty template shows "No placed model elements found in IFC-exportable categories" and no report.
  • For the IFC-02 check, a delivery contract installed on the web project or office, and the model bound through Project Setup. Without one the IFC-01 mapping audit still runs and the dialog says required properties were not checked (no contract).

How to use it

  1. Open the model and make it the active document.
  2. On the Sentinel tab, in the Validate panel, open "IFC Gate" and click "IFC Pre-Flight".
  3. Read the dialog "Sentinel — IFC Pre-Flight": either a clean message or the number of issues across the number of elements checked.
  4. Open the Sentinel pane for the detailed list under rules IFC-01 and IFC-02 and fix them in the model (set 'Export to IFC As' on the type, fill the missing parameters).
  5. Run it again until it is clean, then run IFC Delivery Gate.

What you get

  • A summary dialog with the counts, the time taken, and a line about any requirements not checked here.
  • The Sentinel pane opens and lists the findings as issues under IFC-01 and IFC-02.
  • Nothing is changed in the model.

Tips and limits

If the dialog says required properties are not checked, the contract line tells you why: model not bound, nothing installed, or the contract could not be fetched.
A clean pre-flight is not a certificate. Only the IFC Delivery Gate or Governed Publish judges the exported file.

Related tools

  • IFC Delivery Gate — Exports the model to IFC (or opens an existing IFC) and certifies it against the delivery contract, recording the verdict on the project ledger.
  • Governed Publish — Publishes the whole model to the web project through the one governed path: IFC export, delivery gate, IDS and naming check, then a registered version on the ledger.
  • Show Panel — Opens the dockable Sentinel pane, which shows the model's live rule results, the project's journey from the web, and the Doctor log.
  • Project Setup — Binds the open model to its web project and sets the project code, ghost source folder and Revit Doctor option.

Ribbon tooltip

Audit Export-to-IFC mappings and the delivery contract's required properties BEFORE exporting IFC.
