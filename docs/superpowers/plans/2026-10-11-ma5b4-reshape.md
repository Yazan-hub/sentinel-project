# MA-5b-4 — Reshape with an as-placed stale guard (C13b) — as built

**Goal:** a revised drawing's moved or re-lengthened wall moves the wall the earlier drawing placed — unless a person edited that wall by hand
since it was placed: then Revit keeps it as it stands and says so. Drill MA5's revision row: "B updates its walls, keeps the hand-edited ones,
and flags the deletions for a person".

**Spec:** docs/strategy/2026-09-30-model-automation-design.md :391-394 (protect manual edits; never delete automatically); MA-5b-3's plan
(C13a) and its Horizun notes (the as-built record is what a change is judged against; no record → review, never a guess). Founder: "go ahead
with MA-5b", "can u run all phases all together?" (2026-10-11).

## Decisions (as built)

1. **A new op, `reshape`** (kind wall only): `{op: "reshape", target: {unique_id: <A's placed wall>, placed: {start, end} (the line A placed it
   with)}, place: {LocationCurve: {start, end} (B's trimmed line)}}`. **The bridge's only:** refused when posted (a body cannot move an
   existing wall); built by the drawing planner from a revision. Never pre-ticked; the wall's type is kept (a TypeName on it is refused).
2. **When the planner reshapes** (MA-5b-3's "changed"): the same thickness, ONE wall of A on ONE wall of B (no split, no merge), and A's wall
   placed in Revit (it has a UniqueId). Otherwise it stays a person's row: a thickness change (a retype would move a face), a split or merge,
   or a wall A only proposed.
3. **The stale guard is the as-placed line, in Revit** (no stamp change, no listener): the executor reads the wall's location line now; within
   2 mm of `target.placed` (either way round; Horizun's point tolerance is 1 mm) → the new line is set (hosted doors and windows follow);
   otherwise the wall was edited by hand → **kept** as it stands. A wall gone, or no longer straight, is kept too.
4. **Kept is not a failure:** the rest of the changeset is applied; each kept reshape is reported to the bridge as rejected with its reason
   (the changeset partially applied, the reason on its ledger row), and the result's note says how many walls were kept.
5. Order: reshapes run after every create (a door B adds on a moved wall is hosted at its old line, then moves with it) and before any
   retype.

## Review (wf_31ad0cbe-660) — 1 critical + 4 important confirmed, all fixed

- **Critical: a kept reshape threw after the commit** (`whys[g]` on a null dictionary when nobody typed a reason — the usual "tick all"),
  so the result was never saved or reported and a second Apply would duplicate the creates. Now created lazily.
- **priorOf ignored applied reshapes:** the next revision compared with A's old line (a false "edited by hand" keep, a wall never moved
  back, a door hosted on the old line). Now the chain's newest APPLIED reshape is where the wall stands; a kept one moved nothing.
- **A binding decline of a reshape was never carried:** `carryKey` keys a reshape on its wall, placed line and new line (to the mm).
- **A swapped match reversed the wall** (faces swap): the new line now runs the wall's own way.
- **A pinned, grouped or borrowed wall was moved or failed the whole changeset:** kept as it stands, with why.
- Minors fixed: rooms run after the reshapes (a room a revision closes sees the moved wall); the Revit dialog names the kept walls and why;
  the guard is "still on its placed line" — ends may move along it (Revit's corner joins stretch an untouched neighbour's end, which the
  first guard would have called a hand edit); a door B adds on a wall it reshapes waits for the next proposal; a reshape that would leave a
  door A placed beyond the wall's end is a person's row; the desk's Highlight words name a reshape's Revit id. Kept as ponytails: a locked
  dimension rolls the changeset back in Revit's words; a door B resizes is the same door.
